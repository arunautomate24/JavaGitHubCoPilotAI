# Testing Scenarios Document: Movie Booking App

| Field | Value |
|---|---|
| **Product** | Movie Booking App (console demo) |
| **Related Files** | `MovieBookingApp.java`, `MovieBookingApp_PRD.md`, `MovieBookingApp_Wireframe.md` |
| **Perspective** | **End-user (Ticket Buyer)** — all scenarios are written as console interactions: what the user sees, what the user types at each prompt, and what the user should see as a result. No internal method calls or unit-test steps are referenced. |
| **Scope** | Functional Positive, Negative, and Boundary scenarios covering: browsing movies, viewing movie details, hero actions (Play/Watchlist/Like), choosing a showtime, selecting seats (default/manual/AI random), booking & confirming tickets, and the planned "My Bookings" cancellation & refund flow. |

## Traceability Notes

- Scenarios TC-001 to TC-039, TC-051 to TC-055 validate the **currently working** end-user flows in `MovieBookingApp` (catalog browsing, movie details, hero actions, showtime selection, seat selection, booking, and confirmation), matching PRD Epics 1–6.
- Scenarios TC-040 to TC-050 validate the **"My Bookings" cancellation & refund experience** described in `MovieBookingApp_Wireframe.md` (Section 7) and PRD Epic 7. This screen and flow are **designed but not yet available to end users** in the current console menu — these scenarios should be re-run once the "My Bookings" option is added to the main menu, and are included here so the refund policy (100% / 50% / 0%) is tested from the user's point of view as soon as it ships.
- All scenarios assume the user interacts only through the console prompts shown to them; no scenario requires access to source code or internal APIs.
